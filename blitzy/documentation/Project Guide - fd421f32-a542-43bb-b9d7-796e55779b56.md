### Troubleshooting

| Symptom | Cause | Resolution |
|---|---|---|
| `./hello.sh: Permission denied` (exit 126) | The file is mode 644 with no shebang, deliberately: a shebang would double the file to two lines and breach the fewest-lines requirement | Run it as `sh hello.sh`. Do not add a shebang or an executable bit |
| Nothing printed and exit status 1, with a message such as `echo: I/O error` | The standard output cannot receive the bytes — for example `sh hello.sh >/dev/full` or a closed descriptor (`>&-`) | Redirect to a writable destination. The message comes from the shell's own write-failure path, not from a branch in the program |
| `sh: 0: getcwd() failed: No such file or directory` on stderr, but the correct 18 bytes on stdout and exit 0 | The working directory was deleted before the shell started | Change to an existing directory and re-run; this is the shell's startup diagnostic and the program's output is unaffected |
| `shellcheck: command not found` (exit 127) | No shell linter is installed on this host | Use the parse checks instead: `sh -n hello.sh`, `dash -n hello.sh`, `bash -n hello.sh`, `bash --posix -n hello.sh` — all exit 0. Do not add a lint configuration to the repository |
| A digest or byte count does not match | The checkout rewrote LF endings, or the file was edited | Restore the file to LF (or re-author the literal line) and re-run the acceptance block. Do not relax the contract and do not adjust the expected digest |
| `Permission denied` reading `hello_world.txt` as another user | A checkout created under a restrictive umask can leave the file unreadable by others; the read bit is not versionable by git | `chmod 644 hello_world.txt`. Do not add `.gitattributes` to try to encode it |
| The program's token count reads 2 rather than 4 | Lexical counting differs from the whitespace-word measure the contract states | The contractual figures are 1 line and 25 bytes; `wc -w` gives 4 |
